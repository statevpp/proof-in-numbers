Единственото нещо, което платформата (YouTube) буквално не позволява да се автоматизира отначало, е финалният превключвател "частно → публично" за нови, неодитирани приложения — това не е мой избор на дизайн, а твърдо техническо ограничение на YouTube API. Решението: подаваш audit заявката в Ден 1 (не в Ден 7), за да изтече чакането успоредно с изграждането на пайплайна, и докато чакаш одобрение (обичайно 1-2 седмици), веднъж седмично отваряш YouTube Studio за 2 минути и пускаш всички насъбрани частни видеа наведнъж вместо едно по едно. След одобрението пайплайнът публикува директно през API, без никакъв клик от теб.

## 7-дневен план за изграждане (самото изграждане отнема твоето време само тези 7 дни — след това 0 ръчна работа)

**Ден 1 — Repo, данни, и подаване на audit заявката веднага**
Създаваш GitHub repo. Пишеш скрипт, който тегли статистики от 3-4 безплатни източника (World Bank, Eurostat, FRED, Our World in Data) в ротация — не избираш ръчно всеки ден, скриптът автоматично тегли няколко кандидата и Gemini преценява кой е "най-изненадващ" за деня. **Същия ден** подаваш YouTube API Audit and Quota Extension Form (Google Cloud Console) — това е формуляр, чакането тръгва веднага, паралелно с останалите 6 дни изграждане.

**Ден 2 — Генериране на скрипт + автоматична фактическа проверка**
Gemini промпт генерира {hook, разказ, заглавие, текст за корица, описание}. Добавяш втора, автоматична Gemini стъпка, която препрочита собствения резултат и маркира несъответствия с суровите данни (проста self-check верига — не е нужен човек, само второ извикване на модела с ролята "провери фактическата точност спрямо тези числа").

**Ден 3 — Графика с реални данни**
Python + matplotlib скрипт, изцяло автоматичен — взима суровите данни и текста, генерира стилизирана графика.

**Ден 4 — Глас**
Gemini TTS генерира .wav автоматично от скрипта.

**Ден 5 — Монтаж + технически self-check**
ffmpeg монтаж (говор + графика + субтитри + брандинг) — автоматично. Добавяш `ffprobe` проверка накрая на скрипта: дължина на видеото в разумен диапазон, наличие на аудио писта, липса на дълга тишина. Ако проверката гръмне — workflow-ът маркира run-а като неуспешен вместо да качи счупено видео, без да ти пише за всеки отделен run (виждаш само ако наистина има проблем, чрез GitHub Actions failure notification).

**Ден 6 — GitHub Actions + автоматично качване**
Целият workflow се свързва в едно: `apt-get install ffmpeg`, `chmod +x`, secrets, дневен cron. Добавяш и последна стъпка — качване през YouTube Data API v3 директно от workflow-а (не от твоя компютър) като частно видео с готови заглавие/описание/тагове. Тествайки с ръчно "Run workflow".

**Ден 7 — Канал, брандинг, и пилотна партида**
Настройваш канала (име, банер — може с AI-генерирано лого през Nano Banana/Gemini image, без дизайнер). Пускаш 3-5 пилотни run-а. Единствената ти ръчна задача оттук нататък: веднъж седмично отваряш YouTube Studio, маркираш насъбраните частни видеа като публични (2 минути), докато audit-ът (подаден в Ден 1) не бъде одобрен — тогава и това отпада.

## Очаквани приходи — реалистична рамка (непроменено, не е свързано с автоматизацията)

YouTube Shorts монетизация изисква 500 абонати + 3 млн. гледания на Shorts за последните 90 дни, преди да започне рекламен приход.

| Период | Реалистичен сценарий | По-оптимистичен сценарий |
|---|---|---|
| Месец 1-3 | Под прага за монетизация. Приход: **0 лв** | Ранен momentum. Приход: **0-100 лв** |
| Месец 3-6 | Прагът все още несигурен; RPM нисък. Приход: **0-300 лв/мес** | Стабилен растеж, монетизиран. Приход: **300-800 лв/мес** |
| Месец 6-12 | Умерена аудитория, начален афилиейт. Приход: **150-600 лв/мес** | Добра ниша + партньорства. Приход: **800-2500 лв/мес** |

Ориентировъчни оценки, не гаранция — зависят от алгоритъма и конкуренцията в нишата.
